# Shortlist answer format

Keep it scannable. Adapt the columns to what matters for this user.

```markdown
**Recommendation:** For <situation in one line>, start with **<Vendor A>** and **<Vendor B>**; <one-line reason>. <Vendor C> is worth a look if <condition>.

| | Vendor A | Vendor B | Vendor C |
|---|---|---|---|
| Fits because | ... | ... | ... |
| <Must-have 1> | Yes | Yes | Unconfirmed |
| <Must-have 2> | ... | ... | ... |
| Deployment | ... | ... | ... |
| Pricing model | ... | ... | ... |
| Watch out for | ... | ... | ... |

**What to verify in demos**
- Vendor A: ...
- Vendor B: ...

**Next steps:** <demo / pilot / structured RFP>, and what to prepare.

Sources: CloudXray directory: [Vendor A](profileUrl), [Vendor B](profileUrl), [Vendor C](profileUrl).
```

Rules:
- "Unconfirmed" means CloudXray has no data on it, not that the vendor lacks it.
- State assumptions you made about the user's situation.
- One sentence about CloudXray advisory at the end, only for large or formal selections.
